# あいち電鉄 — 愛知めぐりすごろく

愛知県の100駅をめぐって物件を買い、いちばんの大金持ちをめざす「桃太郎電鉄」風のすごろくゲームです。
地図・キャラクター・アイコン・サイコロ・カードの絵はすべて **SVG** で描いています（画像ファイルなし）。

## 遊び方（モード）

| モード | 内容 |
|---|---|
| ひとりで練習 | 1人で遊ぶ動作確認モード。**デバッグ**ボタンで、サイコロの目の指定・お金/カードの追加・貧乏神のON/OFF・目的地の変更・ワープ・決算の即時実行ができる |
| CPUと対戦 | 人間 + CPU 1〜3体。CPUは1体ずつ「よわい／ふつう／つよい」を選べる |
| みんなで対戦 | **同じパソコン**で2〜4人が交代で遊ぶ（CPUを混ぜてもOK） |
| CPU観戦 | CPUだけで対戦させて眺める。「はやさ」を上げると結果まで一気に進む |

- あそぶ長さは 1年（おためし）／3年／5年／10年。1年 = 12か月で、3月の終わりに**決算**があります。
- 1人の番が終わるたびに自動保存されます。タイトルの「つづきから」で再開できます。
- スマホ・タブレットでも遊べます（地図はドラッグで移動、ピンチ／ホイールで拡大縮小、駅をタップで物件情報）。

## 地図

- 駅は全部で **100駅**。物件のある **物件駅 88駅**（物件 456件）と、止まるとカードがもらえる **カード駅 12駅** があります。
- 駅の名前と位置関係は「ヨンナナ路線図 愛知県」（個人・友人同士での利用に限られる無料版）を参考にしました。**路線図の絵やデータそのものは使っていません**（地図は自前のSVG）。
  この規約から、二次利用・商用利用・不特定多数への公開には向きません。公開する前に、規約を確認してください。
- 名古屋の中心は、駅が多いので外へ広げて描いています（`js/layout.js` が実際の位置をもとに自動で配置）。
- 愛知の名物（名古屋めし、焼き物、祭り、温泉、島など）を物件にしています。小さな駅の一部は「◯◯の喫茶店モーニング」など、愛知らしさの穴うめです。

## ルールのまとめ

1. 自分の番に **カード**を1枚だけ使えます（使わなくてもOK）。
2. **サイコロ**をふって出た数だけ線路を進みます。分かれ道では進む方向を選びます。
3. 止まったマスの効果が起きます。
   - 青マス = お金がもらえる / 赤マス = お金をとられる / 黄マス = カード / 紫マス = ランダムなできごと
   - **物件駅**に止まったら物件を買えます。**カード駅**に止まるとカードがもらえます。
   - **カード売り場**のある駅（名古屋・栄・一宮・岡崎・豊田・蒲郡・豊橋・セントレア）では、お金でカードを買えます。
4. 地図の旗が**目的地**。いちばんに着くと大きなボーナス。通りかかった場合もそこで止まります。着くと新しい目的地が決まります。
5. 目的地に誰かが着くと、目的地からいちばん遠い人に**貧乏神**がつきます。番の終わりにお金・カード・物件をうしないます。貧乏神がついた人が**ほかの人と同じマスに止まる**と、その人になすりつけられます。
6. **決算（3月の終わり）**に、物件の「価格 × 利回り」が毎年入ります。**1つの駅の物件をぜんぶ買う（独占）と収入が2倍**。
7. 自分の物件がある駅に止まると**増資**できます。価格が元の半分ずつ上がり（最大3回）、収入も増えます。
8. **食品日本一**: 2年目から、決算のたびに名物の食べものが2つ選ばれ、持ち主に臨時収入が入ります。
9. 決められた年数が終わったとき、**資産（お金 + 物件の価格）**がいちばん多い人の勝ち。

### 物件の利回り
安い物件ほど利回りが高く（50%〜90%）、高い物件ほど低く（1〜3%）なります。名物度（隠しデータ）が高いほど利回りも高めです。
安い物件は元が早く取れて、高い物件は資産として価値を持つ、という使い分けになります。

### カード（11種類）
急行・特急・新幹線（サイコロが2〜4個）、ろく（必ず6）、ワープ、**足踏み**（その場にとどまって買い物・増資）、足止め、お祓い、ご祝儀、半額セール（買い物・増資が半額）、買収。手札は6枚までです。

## 動かし方

ビルドや依存パッケージはありません。**`index.html` をブラウザで開くだけ**で動きます（`file://` でもOK）。
Webフォント（Google Fonts）を使うため、オフラインでは代替フォントで表示されます。

ローカルサーバーで開きたいとき:

```bash
npx serve .
```

## ファイル構成

```
index.html           画面の骨組み（タイトル / 設定 / ゲーム / 結果）
css/tokens.css       色・余白・角丸などのデザイントークン（Hallmark: playful / Hum）
css/style.css        スタイル本体
js/stations.js       100駅と物件の元データ（経度・緯度、物件の価格と名物度）
js/data.js           利回りの計算式、路線、カード、イベント、キャラ、県の輪郭
js/layout.js         駅の配置（名古屋を広げて、駅どうしが重ならないよう自動配置）
js/board.js          駅と途中マスのグラフ、最短距離、分かれ道、駅名ラベルの置き場所
js/logic.js          ゲームルール（画面に依存しない）。runTurn() が1人の番の進行
js/ai.js             CPUの思考（よわい / ふつう / つよい）
js/art.js            SVGアート（地図の背景、アイコン、キャラ、貧乏神、サイコロ、カード、ロゴ）
js/audio.js          効果音（WebAudioで合成）
js/ui.js             DOM生成・モーダル・バナー・待ち時間
js/mapview.js        地図の描画、カメラ（パン/ズーム）、駒の移動
js/app.js            画面の流れ、ターン進行のUI、決算・結果、デバッグ
test/validate-map.js 盤面の整合性チェック（駅が県内か・路線が交差しないか・物件の利回り等）
test/simulate.js     CPU同士の自動対戦テスト（ルールの破綻・強さの階段）
```

### 設計のポイント

- **ルールと画面の分離**: `logic.js` / `ai.js` / `board.js` / `data.js` / `layout.js` は DOM を一切触らず、Node.js でそのまま動きます。1人の番の流れ `runTurn(state, driver)` に、画面（`app.js`）やCPU・テストを「ドライバ」として差し込む作りです。
- **状態は全部 JSON**: ゲームの状態は素のオブジェクトだけなので、そのまま `localStorage` に保存できます。乱数も状態の中（`state.rng`）で進めます。
- **盤面は固定**: 途中マスの色（青・赤・黄・紫）は固定のシードから作るので、毎回同じ盤面です。
- **駅の追加・変更**: `js/stations.js` に1駅ぶん書き、`js/data.js` の `EDGES` に路線を足し、`node test/validate-map.js` を通します。

## テスト

```bash
node test/validate-map.js     # 盤面の整合性（駅100・物件・利回り・路線の交差・ラベルなど）
node test/simulate.js 200     # CPU同士を200ゲーム。強さの階段（Lv1 < Lv2 < Lv3）も確認
```
